CHAPTER 01

Start here: your first detective duel

Difference Duo is an editable Unity template built around a simple question: what changed between these two pictures? Find every difference before an animated computer-controlled detective does. The opponent is local game logic, not a connected player. No multiplayer server or account service is supplied.

This handbook follows the work you will do: run the game, edit a round, change the look and wording, then build your release. Paths are relative to the Unity project. Keep the game Kit: it supplies the canvas, audio, saving, popups and platform bridge. Szekipapa77 Ads is publisher-owned integration code; third-party advertising SDK binaries are not in the buyer package.

Included content: 25 curated levels, eight illustrated scene backgrounds, 32 prop stickers, five detective rivals, four helpers, first-play guidance, a visual level editor and seeded generation. After the curated bank, the runtime generates further levels deterministically. Online opponents, cloud saves, purchases, LiveOps events and remote backends are not included.

Use the standalone project for a new game or the native unitypackage for an existing project. Import one game per project: private Kits deliberately share class names. Most screens are created at runtime, not stored as editable Canvas children in the scene. Support: szekipapa77@gmail.com.

CHAPTER 02

Installation and first play

Required tools

Use Unity 6000.0.62f1, URP 17.0.4 and Unity UI 2.0.0. Retain the matching official package dependencies and modules listed in the manifest. The game uses Unity UI Text; a separate TextMesh Pro import is unnecessary. Install Android Build Support with matching SDK, NDK and OpenJDK through Unity Hub for Android, and WebGL Build Support for browser builds.

Open the standalone project

  1. Extract the complete source archive to a short writable folder such as C:/UnityWork/DifferenceDuo. Open the folder containing Assets, Packages and ProjectSettings.
  2. Open through Unity Hub with 6000.0.62f1. Wait for package resolution and compilation. Fix the first Console error before proceeding.
  3. Run Szekipapa77 > Difference Duo > Setup. It configures the game pipeline, player settings and entry scenes.
  4. Under Edit > Project Settings > Player > Other Settings, set Active Input Handling to Input Manager (Old), or Both if your project also installs the new input system. New Input System only does not satisfy this game's classic input path.
  5. Open Assets/Games/SpotDuo/Scenes/SpotDuo_Mobile.unity. Press Play, dismiss the introduction with Play and tap the difference indicated by the hand.
  6. Find the remaining differences. The result offers Next Level. Stop Play mode before changing level data or replacing resources.

Import into an existing project

  1. Back up the destination. Install the matching URP and Unity UI versions through Package Manager.
  2. Use Assets > Import Package > Custom Package and import the supplied native package, including the game, Szekipapa77Ads and WebGL template folders.
  3. Run Setup, check input handling and repeat first play. Setup changes rendering and player settings, so inspect those when combining with an existing project.

Preserve .meta files and GUIDs. If resources seem missing, reimport the complete folder rather than inventing new references. The optional Google provider is deliberately absent; simulated ads are expected without it.

CHAPTER 04

Controls, rival, scoring and results

Compare and tap

Tap or click a difference on either picture. Portrait stacks the pictures; landscape places them beside each other. A find is circled in both. SdPicInput.OnPointerDown forwards to SpotDuoGame.OnPicTap, which converts the screen point to picture coordinates before calling Tap. No dragging is required.

A moved object accepts either its original or moved position. Mirrored rounds flip the right picture while keeping hit mapping consistent. Tapping fog clears it without a miss. An already-found target animates its ring without awarding duplicate points. If unfound target areas overlap, the nearest matching difference wins.

Local rival and mistakes

The rival follows a deterministic schedule based on the level. Progress dots show its finds; a speech bubble warns when one remains. Its initial delay and completion time are level data. During the first tutorial it waits for your first find. Game popups stop normal active play through PopupOpen/CanPlay checks.

Three consecutive misses cause Seeing Double and lock the pictures for three seconds while the rival continues. A correct find clears the miss counter. Steady Eyes blocks a limited number of misses, not the entire round.

Points and stars

Each find starts at 100 points, adds a declining speed bonus and can add a streak bonus. Finds less than 2.5 seconds apart build the streak. Winning adds a time-lead bonus. The HUD displays the accumulated total. A win earns one star, another for avoiding Seeing Double and another when the rival found at most half the targets. The best star result for each level is retained.

End and retry

Find every difference before the rival to win. The next level index is saved, then Next Level starts it. If the rival finishes first, Retry repeats the current level. A once-per-round rewarded rescue makes the rival lose its last two finds and continues the round; it depends on a successful earned callback. This is local game state, not a server operation.

CHAPTER 05

First-play and helper tutorials

The tutorial is in SpotDuoGame.Hud.cs: StartTutorial, TutorialFound and StopTutorial. A pointing hand identifies the first difference, then a second tip asks for the rest. The completion flag spotduo_tut persists, so restarting Play mode alone does not reset the lesson. Use a separate development save or clear only the game's relevant test keys.

Helper introductions are separate. UnlockPopup grants initial charges once, StartGuide/RefreshGuide points to the newly available tool, and CompleteGuide records that its first use was taught. The guided first use is free. A returning player may have completed the main tutorial but still need a helper introduction.

New mechanics use the authored level hint, NewKindHint in SpotDuoGame.cs and SdDiffKinds.IntroHint in SdData.cs. For a single level, edit First-time hint in the visual editor. For general tutorial wording, edit the actual methods, preserving interpolated counts and rival names. Shared font or UI-kit settings do not automatically translate these game sentences.

After a tutorial change, check a fresh save and an existing save, portrait and landscape, a return from settings, and the transition after the first find. A guide that looks correct only before the layout refresh is not sufficient.

CHAPTER 06

Four tools, unlocks and charges

ToolUnlock / initial chargesEffect
MagnifierLevel 3 / 3Selects the hardest unfound target, clears fog over it and draws a ring; the player still taps it.
FreezeLevel 6 / 2Stops the rival clock for 10 seconds with a visible frozen portrait/countdown.
RadarLevel 10 / 2Pulses the remaining target areas for 2.6 seconds.
Steady EyesLevel 15 / 2Blocks the next three misses and displays remaining protection.

In SpotDuoGame.cs, BoostUnlock is {3,6,10,15}, BoostStart is {3,2,2,2}. BoostName and BoostArt use the same order. The Hud partial's RefreshBoosters builds locked-level captions and charge badges. Keep parallel arrays aligned.

OnBooster dispatches UseHint, UseFreeze, UseRadar and UseShield. Consume takes a charge except during the free guide. An empty button opens OfferCharge; a successful Watch ad result adds one charge, then the player activates the helper normally. There is no cash purchase system here.

To reduce Freeze duration, change FreezeSeconds from 10 to 8, update matching explanation strings and test the countdown. To move an unlock, edit its array element and start a controlled fresh save; existing seen/guided flags may suppress the first-use flow. Verify locked captions, free grant and tutorial together.

CHAPTER 07

Make one level in the editor

  1. Exit Play mode. Open Szekipapa77 > Difference Duo > Level Editor. Select a level and press Dup to preserve the original.
  2. Set Name, Scene, Rival and First-time hint. Names and hints are player-visible; scene/rival selectors use catalog identifiers.
  3. Choose + Missing and a prop. Click a clear picture area. Switch to Select and drag to adjust. Use the inspector for size, side and hit radius.
  4. Add a Recolour target elsewhere. Choose an obvious alternate tint. Do not cover targets with decoration stickers.
  5. Set Rival finishes at (s) and Rival start delay (s), or use Auto pace as a starting estimate.
  6. Validate the level and resolve warnings. Save writes levels.json and refreshes Unity. Play this level saves, opens the landscape scene at that index and enters Play mode.
  7. Test portrait separately, including small-screen clue visibility. Back up the JSON before large changes.

Tools and gestures

Tools cover Missing, Recolour, Moved, Flipped, Resized, Tinted and Vanished differences, shared Sticker decoration and Fog. Drag a moved difference's second point to change its destination; a clone patch's second point chooses its sampled source. Mouse wheel or square brackets resize; right-click deletes. Keys 1–7 change type, R rotates, F flips, S swaps the changed side, arrows nudge and Delete removes the selected item.

The list provides Add, Dup, Del, Up and Down. Its order is runtime order. Reordering can change the content a saved level number resolves to. Undo, the dirty marker and save-on-close prompt support authoring, but keep independent backups of intentionally large edits.

The inspector shows every selected difference/sticker/fog field, its tap radius and perception estimates. Validate All inspects the whole bank. The curve highlights difficulty, easier breathers and failures; do not interpret bot estimates as guaranteed human difficulty.

Worked append

  1. Back up levels.json. Select the final authored level, 25.
  2. Set Count 3, Start level # 26, Seed 9127, Start difficulty 0.45, End difficulty 0.60 and Breather every 0.
  3. Leave Replace unchecked. Generate inserts three entries after the selection, retaining the existing 25.

Worked replacement

For levels 10–12, use Start level # 10, Count 3 and enable Replace. The implementation clamps the insertion start to the bank's valid bounds, replaces existing entries and appends only if the range runs beyond the current end. It does not create another parallel bank.

Runtime continuation after the curated bank uses SdGen.ForLevel. Editor generation uses the same SdGen family with explicit seeds and a difficulty curve. Validation checks bounds, overlaps, subtlety and estimated bot times/win rates; it cannot replace human inspection of ambiguous clues.

FieldMeaning

mirrorMirrors the right picture and its input mapping.

x/y are normalized 0–1 picture coordinates, y down. Size and radius use picture width. Aspect is 1.5. Difference side 0 places the change on the right picture, side 1 on the left. Exact kind keys are missing, color, moved, flip, size, hue and clone.

Color uses alt for the changed tint; moved uses dx/dy for its displacement; clone uses them for the sampled source offset. Size uses val as changed scale and hue uses it as hue shift. Positive r overrides the automatic hit radius. Use the editor to see these fields before making broad text changes.

Catalog scene colour grids and sticker dimensions support visibility estimates. After a substantial image replacement, inspect catalog assumptions and validate every affected level. Replacing a JPG does not update its perception model automatically.

Worked helper and title edits

To rename Magnifier to Clue Lens, change the first BoostName value. Captions and guides using that array follow. Inspect help/unlock explanations for any hard-coded wording. Keep booster_hint as the resource key and retain the same array order.

Keep technical difference kinds, resource IDs and save keys unchanged unless implementing a planned migration. Preserve interpolation braces, number formatting and newline escapes when translating. CHAPTER 12

Artwork, fonts and audio

Backgrounds, props and rivals

Scenes load from Resources/spotduo/Art/Scenes/scene_<id>.jpg. Keep their 3:2 shape. Stickers are Art/Props/prop_<id>.png with transparency. To replace an existing image, overwrite it while retaining its .meta file. New identifiers need art and catalog entries before being selected in the editor.

Do not leave excessive transparent borders around stickers. Their visual footprint must agree with the catalog. A flipped clue needs an asymmetric prop; a colour clue needs a clearly visible difference from the base art. Test at actual phone sizes, not only a large editor preview.

Rival keys are rival_fox, rival_cat, rival_owl, rival_penguin and rival_raccoon. BoostArt identifies helper files. SdArt caches sprites and scenes; restart Play mode after replacing resources.

Scenery patches

Keep SdPatch.shader and SdPatchMat.mat, including their GUID relationship. Feathered hue and clone-stamp differences depend on the material and extra canvas texture-coordinate channels. Harsh rectangles or missing scenery differences warrant checking shader/material import before replacing backgrounds.

Type and licences

Kit/Resources/spotduo/kit/Fonts contains LilitaOne.ttf, Nunito.ttf and MaterialIcons.ttf. HzUI.Display and Body load the first two; HzIcons.Font loads the icon font. Replace text fonts with suitable licensed fonts and preserve paths or update loaders. An ordinary font cannot replace the icon font's codepoints.

Keep the supplied font notices, including OFL and MaterialIcons licence files. Use a font with glyph coverage for your language and inspect accented letters, punctuation and numbers. Do not put emoji into a font that does not supply them. For any newly added art, music or font, retain the rights evidence outside your runtime assets and supply applicable redistribution notices.

Sound

SdSfx.cs names resource events. Sfx contains find/streak/miss, rival, fog, the four helpers, popup and result sounds. Music uses Music/duo_loop.ogg. Retain basenames or update the matching constants. HzAudio supplies playback and combo pitch. Settings exposes separate sound/music toggles; verify both after replacement.

Balance music beneath clue feedback and test loud transitions for clipping. Marketing voiceover is separate from in-game sound and is not a runtime dependency.

CHAPTER 13

Saving and compatible updates

HzSave in Kit/Runtime/HzCore.cs wraps PlayerPrefs and coalesces writes. Progress uses spotduo_level, score uses spotduo_total and tutorial completion uses spotduo_tut. Charges are spotduo_b0 through spotduo_b3. Initial unlock flags are spotduo_seen0 through spotduo_seen3; guided-use flags are spotduo_guided0 through spotduo_guided3. Best stars use spotduo_stars plus the level number.

Other flags track introduced difference types, fog, mirror and the first Seeing Double explanation. These are an update contract. A visible title rename is safe; replacing every spotduo string can reset progress or break Resources loading. Test migration before making that kind of change.

PlayerPrefs is local, not secure currency storage or cloud synchronization. Browser storage can be cleared or restricted. Android uninstall can remove progress. There is no supplied cross-device account. Cloud saving requires your own provider and migration logic.

A saved level refers to its bank position, not a stable content GUID. Append where possible. Reordering or replacing earlier levels can show different content to returning players at the same saved index. Back up development saves before testing a new bank.

CHAPTER 14

Advertising: included integration and external provider

The buyer source contains Szekipapa77 Ads integration, settings and an optional adapter. It does not contain Google's Mobile Ads SDK or External Dependency Manager. This distinct source edition does not include HyperCasual LiveOpsKit, purchases, LiveOps stores or a remote backend. Do not follow older templates' HLK configuration instructions.

The call path is game → HzPlatform → game Kit HzAds → Szekipapa77.Ads.AdsService. The optional adapter detects a separately installed Google plugin. Real rewards depend on an earned callback; an installed provider failing to show an ad does not silently become a successful simulated reward.

AdsSettings.asset fieldSupplied meaning
backend: 2Requests AdMob. This enum is None=0, Dummy=1, AdMob=2; it is not the HLK enum.
missingSdkFallback: 1Dummy simulation when the provider is absent.
useGoogleTestIds: 1Test application and ad unit IDs if an optional SDK is installed.
dummyDelaySeconds: 0.4Development simulation delay.

loadTimeoutSeconds: 25Ad load waiting budget.

Development

Open Tools > Szekipapa77 Ads > Setup & Diagnostics. With no Google plugin, fallback is simulated. WebGL always simulates because this AdMob adapter does not support browser ads. Simulation tests UI/callback flow; it is not revenue. A separate test-ad Android demo can be compiled with an externally imported SDK without redistributing that SDK in the buyer source.

Configure an optional Google provider

  1. Back up the project. Obtain the official Google Mobile Ads Unity plugin and its dependency manager from Google; import them separately and follow their current platform instructions.
  2. Check detection in the publisher diagnostics window. Keep test IDs enabled while testing. Exercise success, cancellation/failure, earned reward exactly once, banners and interstitial continuation.
  3. Enter your own app ID and format-specific unit IDs in Assets/Szekipapa77Ads/Resources/AdsSettings.asset. Use your account identifiers for your release.
  4. Before a production build, set Missing SDK Fallback to None and disable Use Google Test IDs only after entering valid production IDs. The supplied build tooling refuses a missing-provider release or a release still configured for simulated fallback.
  5. Provide your own privacy policy, consent flow, Privacy Options and required disclosures. Check them on physical devices in the relevant regions. Template configuration alone does not establish compliance or revenue.

Interstitials are throttled to at most one per 60 seconds. Failure/skipping continues game flow once. Phone banners reserve bottom space; inspect camera/layout clearance and device safe areas after reskinning. The game has no supplied production IAP configuration.

CHAPTER 15

Android and browser releases

Android build

  1. Install the Unity-matched Android tools. Run Setup and inspect the portrait scene.
  2. Replace the template application identifier com.szekipapa77.spotduo with your own unique ID. Choose product/company labels, app icon, version and version code.
  3. Review scripting backend and architectures in the actual Android Build Profile. Do not assume a supplied demo is configured for your target marketplace.
  4. Configure the provider as above and run Szekipapa77 > Difference Duo > Build Android. Output is Builds/Android/spotduo.apk.
  5. Use your own production keystore and keep its secrets outside distributable source. A test-signed demo is not production signing. Build an App Bundle if your destination requires it.
  6. Install on physical devices. Check tap edges, tutorials, every helper, miss locks, pause/resume, sound toggles, ads and save persistence.

WebGL build

  1. Install WebGL Build Support and run Setup. The supplied Szekipapa77 template frames a portrait phone layout.
  2. Run Szekipapa77 > Difference Duo > Build WebGL. Output is Builds/WebGL/spotduo.
  3. Upload index.html together with all Build and TemplateData content. Serve over HTTP(S), not file://. Preserve filenames referenced by the loader.
  4. The setup uses compression with decompression fallback. If loading stalls, inspect Console errors and server compression/content headers.
  5. For landscape, explicitly select SpotDuo_WebGL.unity in your Build Profile or adapted build scene list. The standard menu intentionally selects the Mobile portrait scene.
  6. Test desktop mouse, mobile taps, audio after user interaction, storage/reload behavior and the actual hosted page. Browser ads remain simulated.

For each final build, retain size and SHA-256. Verify a complete anonymous download rather than an owner preview. A browser demo does not prove native provider behavior. Your accounts, publishing destinations and signing keys are not runtime dependencies.

CHAPTER 17

Before shipping and getting help

  1. Run both supplied scenes on a fresh installation. Complete a round, restart and verify saved progression.
  2. Exercise first-play and helper guides, all helper effects, miss lock, win/loss/retry and both rewarded success/failure paths.
  3. Validate edited/generated content. Inspect clue readability and refresh paths in both layouts after a reskin.
  4. Review licences, new artwork/font permissions, privacy/consent requirements and current platform rules for your release.
  5. Replace application identity/signing configuration. Import the final package into another clean project to prove independence from caches, private tooling and other games.
  6. Provide this offline handbook before import and inside the project. Verify public demo/manual/video links after publication.
