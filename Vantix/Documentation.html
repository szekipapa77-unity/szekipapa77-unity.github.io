Vantix

A unified runtime diagnostics & developer-operations platform for Unity — console, inspector, logging, telemetry, analytics, performance, bug & crash reporting, a cross-correlated session timeline, QA and live-ops, on one Diagnostics Bus.

Unity 2021.3+ Built-in / URP / HDRP Mono + IL2CPP No external deps
ⓘ
One platform, one data spine. Every Vantix module — logging, console, inspector, performance, telemetry, analytics, crash, QA, live-ops — publishes to a single in-process Diagnostics Bus. The Session Recorder folds all of it into one correlated timeline, so you can see exactly what surrounded a spike, an error or a crash.
🧰
No code required to start. Drop the Vantix Bootstrapper component on a GameObject (or use GameObject → Vantix → Add Vantix To Scene) and press Play. The full developer overlay appears — HUD plus console. See No-Code Setup.

⤓ Installation

Import once. No external packages, no native binaries, no setup step is mandatory.

Import the package
From Window → Package Manager → My Assets, download and import Vantix. It lands at Assets/Vantix/. There are no external package dependencies.
(Optional) Create a settings asset
Tools → Vantix → Create Settings Asset to tune capacities, severity, the kill switch and auto-boot. If you skip this, Vantix uses a built-in default (VantixSettings.GetOrDefault()).
Press Play
On entering Play mode VantixRuntime auto-boots, installs its services, and UIBootstrap spawns the overlay. That's it — nothing else is required to start collecting diagnostics.

Requirements

  • Unity 2021.3 or newer (tested through Unity 6).
  • Render pipeline: Built-in, URP or HDRP — the overlay is a screen-space UI canvas.
  • Scripting backend: Mono or IL2CPP (for IL2CPP, generate the AOT link.xml — see Editor Tools).
  • No external package dependencies.

Kill switch. VantixSettings.Enabled gates the whole platform. Set it to false (or define VANTIX_DISABLED) and Vantix becomes a safe no-op — ideal for stripping it from shipping builds without touching your own code.

⚡ Quick Start

Two ways in: the no-code path with one component, and the code path with one method call.

No-code path

Add Vantix to the scene
GameObject → Vantix → Add Vantix To Scene drops a ready-configured [Vantix] object carrying the Vantix Bootstrapper component. (Or add the component yourself via Add Component → Vantix → Vantix Bootstrapper.)
Press Play
The Bootstrapper initializes Vantix and spawns the overlay — an always-on performance HUD and a toggleable console.
Open the console
Press the backquote key (`) to toggle the console panel, type a command and press Enter.
👋
New here? Open the interactive Welcome scene (Assets/Vantix/Demo/Scenes/Vantix_Welcome.unity) and press Play for a guided, clickable 5-step tour that boots Vantix, opens the overlay and loads the demo — no code required. See No-Code Setup.

Code path

Vantix is a safe no-op until it initializes, then auto-boots on the first Play frame. Just start using the façades:

using Vantix.Logging;
using Vantix.Core;
using Vantix.SDK;
using Vantix.Telemetry;

// 1. Structured logging (channel + typed fields)
VantixLog.Info("Player spawned", "gameplay",
    VxField.Of("hp", 100), VxField.Of("name", "hero"));

// 2. A console command anyone can run in-game
public static class Cheats
{
    [VantixCommand("heal", Summary = "Restore player health.")]
    public static string Heal(int amount) => $"healed {amount}";
}
// then type:  heal 50

// 3. Track a telemetry event
VantixTelemetry.Track("level_complete", VxField.Of("level", 3));C#
💡
Mix and match. The no-code Bootstrapper and the code API coexist. If your code (or auto-boot) already started Vantix, the Bootstrapper detects it and defers — code always wins precedence, so nothing is double-initialized.

⚙ How It Works

The Diagnostics Bus is the spine. Everything publishes to it; the Session Recorder unifies it.

Your game + modules → Publish<T> → Diagnostics Bus → Channels (ring history) → Subscribers → Session Recorder → Unified Timeline
  1. VantixRuntime.Initialize(settings) brings up the core and installs each module's service (auto-boots in Play mode).
  2. Modules publish strongly-typed records — LogRecord, MetricSample, TelemetryEvent — via IDiagnosticsBus.Publish<T>(in T).
  3. Each Channel<T> keeps a bounded history ring plus zero-alloc, copy-on-write subscribers, so reading recent history never blocks publishers.
  4. Services subscribe to the channels they care about (logging fans to sinks, performance to alerts, analytics to aggregations, …).
  5. The SessionRecorder folds logs, telemetry, metrics and markers into one correlated timeline you can query and export.
ⓘ
In-process and allocation-aware. The bus is pure C#, runs entirely in your process, and is built around ring buffers, an ObjectPool<T> and the low-alloc VxField KVP. There is no server, no socket and no per-frame garbage in steady state.

The pieces of Core

TypeRole
VantixRuntimeLifecycle: Initialize / Shutdown / Flush; exposes Bus, Context, Dispatcher, Clock, Settings, Session.
IDiagnosticsBus / Channel<T>Publish<T>, Subscribe<T>, GetChannel<T>, NextSequence; bounded history + copy-on-write subscribers.
RingBuffer<T> / ObjectPool<T>Bounded buffer with an overflow policy and dropped-count, plus pooling primitives.
VantixContext / VantixDispatcherInterface-keyed service registry; main/worker dispatch.
VxFieldMostly allocation-free typed key/value — the structured field used across logging, telemetry and metrics.

🖥 Runtime Console

Vantix.Console — an in-game developer console with attribute-driven commands, cvars, autocomplete and history.

Decorate any method, property or field with [VantixCommand] to turn it into an invokable command; [VantixVariable] exposes a field/property as a runtime variable (cvar) you can read and set from the console.

using Vantix.SDK;

public static class DebugCmds
{
    [VantixCommand("spawn", Category = "player", Summary = "Spawn N enemies.")]
    public static string Spawn(int count) => $"spawned {count}";

    [VantixVariable("god_mode", Summary = "Invulnerability.", Privileged = true)]
    public static bool GodMode;
}C#
// Execute from code (the overlay does this for you on Enter):
CommandResult r = ConsoleService.Execute("spawn 5");
string[] suggestions = ConsoleService.Complete("sp");   // autocomplete
CommandRegistry.ScanType(typeof(DebugCmds));      // or manual Register(...)C#
MemberDescription
[VantixCommand]Id, Category (slash/dot path), Summary, Privileged (hidden in non-dev builds).
[VantixVariable]Same options — exposes a field/property as a get/set cvar.
ConsoleService.Execute(line)Parses + binds arguments and runs a command → CommandResult.
Complete(prefix) / HistoryAutocomplete suggestions and command history.
IArgumentConverter / ConverterRegistryBuilt-in primitives + enums; register converters for your own types.
AllowPrivilegedGate that enables/denies privileged commands and variables.

🔎 Runtime Inspector

Vantix.Inspection — reflect over live objects at runtime, read and edit member values, and watch fields for change.

InspectorService.Inspect(target, label, depth) walks an object into a lazy, bounded InspectorNode tree; values are read and written through cached, AOT-safe reflection. Mark members with [VantixWatch] for change notifications, or a whole type with [VantixInspectable] to surface it.

using Vantix.Inspection;
using Vantix.SDK;

[VantixInspectable("Player")]
public class Player : MonoBehaviour
{
    [VantixWatch("Health")] public int hp;
}

// Build an inspector tree for any live object:
InspectorNode root = InspectorService.Inspect(player, "Player", depth: 2);
string shown = ValueFormatter.Format(player.hp);C#
MemberDescription
ReflectionCache.GetMembers(type, MemberFilter)Cached, AOT-safe member discovery.
InspectableMember.TryGetValue / TrySetValueRead/write a member value safely.
InspectorService.Inspect(target, label, depth)Lazy, depth-bounded InspectorNode tree.
[VantixWatch] / [VantixInspectable]Watch a field for change; mark a type as inspectable.
ValueFormatter.Format(value)Human-readable formatting for displayed values.

📝 Logging

Vantix.Logging — structured, channelled, correlated logging that flows onto the bus and the timeline.

The VantixLog façade has a level per severity, each taking a message, a channel and optional typed VxField fields. Wrap related work in a LogScope to attach a thread-local correlation id, so everything inside it lines up on the timeline.

using Vantix.Logging;
using Vantix.Core;

VantixLog.Trace("verbose detail");
VantixLog.Info("Saved game", "io", VxField.Of("slot", 2));
VantixLog.Warn("Low ammo", "gameplay");
VantixLog.Error("Bad config", "boot", VxField.Of("key", "volume"));

try { /* ... */ }
catch (Exception e) { VantixLog.Exception(e, "gameplay"); }

using (new LogScope())          // correlate everything in this scope
{
    VantixLog.Info("begin checkout", "shop");
    VantixLog.Info("end checkout", "shop");
}C#
  • Severities: Trace, Debug, Info, Warn, Error, Fatal, plus Exception(ex).
  • Sinks: InMemoryRingSink for recent history, LogFormatter for rendering; UnityLogBridge ingests Debug.Log so existing logs join the bus.
  • LoggingService fans bus log records out to sinks; a RollingFileSink persists logs when File Logging is enabled; LogRedactor can scrub sensitive fields.
💾
Persisting logs. Logs live in memory by default. Enable File Logging (on the Bootstrapper, in the settings asset, or via VantixSettings.FileLogging) to write a rolling file you can collect after a session.

🔥 Performance Diagnostics

Vantix.Performance — live frame, fps and memory metrics with a HUD and threshold alerts.

PerformanceService ticks each frame and publishes frame.ms, fps and memory metrics to the bus; FrameStats tracks avg/min/max/fps. The HUD in the overlay graphs frame time live. Add an AlertRule to fire an action when a metric crosses a threshold.

using Vantix.Performance;
using Vantix.Logging;

service.Alerts.Add(new AlertRule
{
    Metric    = "frame.ms",
    Op        = Comparison.Greater,
    Threshold = 33,
    OnTrigger = (s, r) => VantixLog.Warn("Frame spike!", "perf")
});C#

Add your own metric by decorating a method or property with [VantixMetric] — give it a Name and optional Unit, and it is collected alongside the built-ins.

[VantixMetric("enemies.alive", Unit = "count")]
public static int AliveEnemies => _enemies.Count;C#

📡 Telemetry

Vantix.Telemetry — named events with typed properties, sampled, buffered and flushed.

VantixTelemetry.Track(name, …) builds a stamped TelemetryEvent (with session id and sequence) and publishes it to the bus, where TelemetryService samples, buffers and flushes it. It is a safe no-op before the runtime initializes.

using Vantix.Telemetry;
using Vantix.Core;

VantixTelemetry.Track("level_complete",
    VxField.Of("level", 3),
    VxField.Of("seconds", 84.2));C#
  • TelemetryService applies sampling, keeps a bounded buffer, and Flush() hands batches to its OnFlush sink.
  • Declare an event emitter with [VantixEvent("name")].
  • Serialization and an HttpTransport are provided for sending events on if you wire a destination.

📊 Analytics

Vantix.Analytics — on-device aggregation of telemetry and metrics into counts, histograms and KPIs.

AnalyticsService consumes telemetry events and metric samples off the bus and turns them into queryable aggregates — counters, histograms with percentiles, and named KPIs you define.

using Vantix.Analytics;

int wins = analytics.EventCount("level_complete");
Histogram h = analytics.MetricStats("frame.ms");   // min/max/mean/percentile

analytics.RegisterKpi("retention", () => ComputeRetention());
var value = analytics.EvaluateKpi("retention");
DevStats snapshot = analytics.Snapshot();C#
  • EventCount(name) — total occurrences of a telemetry event.
  • MetricStats(name) → Histogram with min/max/mean and percentiles.
  • RegisterKpi / EvaluateKpi — define and read derived metrics.
  • Snapshot() → a DevStats roll-up for display or export.

📈 Visualization & Dashboards

ChartSeries + ChartGeometry build line, bar and range charts drawn by a mesh-batched ChartView : Graphic (one draw, no per-point overhead). Charts bind to an IDataSource — pull from a metric mean, an event count, a delegate, or a no-code data table.

TypePurpose
ChartSeries / ChartGeometrySeries data and line/bar/range geometry.
ChartView : GraphicMesh-batched UI chart renderer.
IDataSourceDelegateDataSource, MetricMeanDataSource, EventCountDataSource.

ⓘ
No-code data. A VantixDataTable asset (Assets → Create → Vantix → Data Table) holds tabular data — importable from CSV with the delimiter auto-detected — and feeds chart series straight from a named column. See No-Code Setup.

🐛 Bug Reporting

Vantix.BugReport — one-call reports stamped with device, build, session and log breadcrumbs.

BugReportService.CreateReport(…) snapshots the current device info, build info, session and recent log breadcrumbs into a structured report. Attach files or a screenshot, build a manifest, and submit it through any IVantixTransport.

using Vantix.BugReport;

BugReport report = BugReportBootstrap.Service.CreateReport(
    "Stuck in wall", severity: BugSeverity.High);

report.AddAttachment("save.json", bytes);
service.TryCaptureScreenshot(report);
service.Submit(report, transport, dest);C#
  • CreateReport(title, notes, severity, repro) — device/build/session + log breadcrumbs.
  • AddAttachment, TryCaptureScreenshot, BuildManifest, Submit(report, transport, dest).
  • Severities via BugSeverity; payload types BugReport / Attachment.

💥 Crash Diagnostics

Vantix.Crash — automatic capture, signature-based dedupe, crash-safe persistence and next-boot recovery.

Unhandled managed exceptions are captured automatically. Each crash is reduced to a normalized CrashSignature so duplicates fold into one CrashGroup; pending crashes are persisted crash-safely and recovered on the next boot, then exported through an ICrashExporter.

using Vantix.Crash;

// Manual capture (automatic for unhandled exceptions):
service.Capture(exception, isFatal: false);
service.Capture(type, msg, stack, fatal: true);

var sig = CrashSignature.Compute(exception);   // dedupe key
service.RecoverPersisted();                       // on next bootC#
  • Capture(exception, isFatal) / Capture(type, msg, stack, fatal).
  • CrashSignature.Compute — normalized dedupe; grouping via CrashGroup.
  • PersistPending / RecoverPersisted — crash-safe + next-boot recovery.
  • BuildExportPayload + the ICrashExporter seam to ship crashes onward.
⚠
Scope. Vantix captures managed (C#) exceptions. Native crashes (engine/plugin-level) are not catchable in managed code and are out of scope.

⏱ Session & Unified Timeline

Vantix.Session — the cross-correlation differentiator: every signal on one queryable, exportable timeline.

SessionRecorder folds logs, telemetry, metrics and markers into a single timeline. Query by time, kind, severity or correlation id to see exactly what surrounded a spike or an error, then export the whole session for a teammate to import and replay.

using Vantix.Session;

recorder.Mark("boss fight start");
recorder.Record(timelineEvent);

var hits = recorder.Query(new TimelineFilter
{
    Kind     = TimelineKind.Log,
    Severity = LogSeverity.Error
});

string json = recorder.Export();   // share with a teammate
recorder.Import(json);                 // reload on their machineC#
  • Mark(label), Record(event) — place markers and fold in events.
  • Query(TimelineFilter) — filter by time, kind, severity or correlation.
  • Export() / Import() — portable session snapshots.
  • TimelinePlayer — a scrub cursor for stepping through a session.

✅ QA Toolkit

Vantix.QA — structured test sessions, annotations, bookmarks and repro recording.

QaService wraps a play session in QA structure: start/end a session, annotate moments, drop bookmarks, flag a bug (which seeds a BugReport), and record reproduction steps.

using Vantix.QA;

qa.StartSession("smoke pass");
qa.Annotate("weird audio glitch here");
qa.AddBookmark("level 3 entrance");

qa.BeginRepro("door won't open");
qa.RecordStep("pull lever");
qa.RecordStep("walk to door");
qa.EndRepro();

qa.MarkBug("door soft-lock");   // seeds a BugReport
qa.EndSession();C#

📱 On-Device Dev Overlay & Dominator Features

The turnkey Dev Overlay is a single drop-in — GameObject → Vantix → Add Dev Overlay To Scene, or add the Vantix Dev Overlay component — that assembles a tabbed, on-device developer console: Console, Logs, Performance, System Info, Options, Bug Reporter. Toggle it on device with the backquote key, a multi-tap touch gesture, or the on-screen floating button. No scripting required.

  • Console — fuzzy autocomplete with Tab-cycle + ghost completion, severity-colored output, command groups/aliases, persistent history, async/cancellable commands, and Vector/Color argument converters.
  • Logs — severity filter + counts, free-text search, consecutive-duplicate collapse, expandable stack traces, copy/clear, color-by-severity.
  • Performance — FPS (cur/avg/min/max), frame time, memory (managed/used/reserved), GC gen0–2 + alloc, render stats (draw calls/batches/tris/verts) and audio level, with basic/advanced modes and threshold color.
  • System Info — device/OS/CPU/GPU/RAM, graphics API, quality, build (device id redacted for privacy).
  • Options — every registered cvar / [VantixVariable] shown as a toggle/field and written straight back.
  • Bug Reporter — title/notes/severity + screenshot, assembling a real report with device/build context and recent log breadcrumbs.

Crash exporters. Beyond Sentry and Bugsnag, Vantix exports to a generic webhook and a Crashlytics-compatible JSON format (an original mapping — not the Firebase native SDK/NDK; native crash/ANR/OOM capture is impossible in managed C# and remains out of scope), with auth headers, enriched breadcrumbs, and an offline queue + retry pipeline.

Local remote web console (desktop). An optional, local-first module serves a browser console over the LAN via an embedded HTTP server (live log stream, remote command execution, system status) — there is no cloud backend. It is OFF by default, loopback-bound and token-gated, excluded on WebGL, and experimental on iOS/Android. Start it with the remote.start console command. Never enable it in shipping consumer builds.

All of the above is original, copyright-clean, AOT/IL2CPP-safe managed code, verified by headless Unity 6: EditMode 286 · PlayMode 33 · IL2CPP + Mono + WebGL builds Succeeded · 0 compile errors. On-GPU and in-browser appearance is a human-visual pass.

🧰 No-Code Setup

A complete, no-scripting path: one drop-in component, a Welcome window, a hub, a wizard and Project Settings.

⭐
Headline capability. You can stand up the entire platform — overlay, console, HUD, file logging — without writing a line of code. The no-code path is additive to the scripting API and always defers to code that already started Vantix.

Vantix Bootstrapper (drop-in component)

The VantixBootstrapper MonoBehaviour is the no-code entry point. Add it via Add Component → Vantix → Vantix Bootstrapper, or use the menu below to get a pre-configured object. On Awake it initializes Vantix from its Inspector options — but only if Vantix isn't already up (code and auto-boot win precedence).

  • Settings Asset — optional; empty uses the project default.
  • Show Overlay — spawn the HUD + console on play (on by default).
  • Enable File Logging — persist logs to a rolling file (overrides the settings asset when ticked).

Its custom inspector adds one-click buttons: Create Settings Asset, Open Control Center and Setup Wizard.

GameObject → Vantix → Add Vantix To Scene

This menu item creates a [Vantix] GameObject with the Bootstrapper already attached, registers an Undo step, selects and pings it — then you just press Play.

First-run Welcome window

On first import a Welcome to Vantix window opens automatically (once; suppressed in batch/CI; dismissible forever). It has buttons to Add Vantix To Scene, open the demo scene, open the interactive Welcome scene, run the Setup Wizard, open this documentation and open the Control Center, plus a 3-step quick start. Re-open it any time from Tools → Vantix → Welcome.

Interactive Welcome scene

Prefer to learn by doing? Open Assets/Vantix/Demo/Scenes/Vantix_Welcome.unity and press Play — or generate it head-lessly with Tools → Vantix → Build Welcome Scene. It's a guided, in-game 5-step tour (Welcome → Add to your scene → Dev Overlay → Explore the demo → Extend & get help) with a step rail and a detail pane, styled to match the asset. Every step has live actions that really run: boot Vantix, open the real on-device Dev Overlay on top of the scene, load the full interactive demo, copy ready-to-paste code snippets, and open this documentation. It runs in the Editor, in standalone players and in WebGL, so it doubles as a zero-setup showcase you can hand to teammates.

VantixDataTable — CSV import

Create a data table via Assets → Create → Vantix → Data Table. Import a CSV and Vantix auto-detects the delimiter (or pass one explicitly), infers a per-column type (Numeric / Category / Text), and exposes numeric columns by name so a chart series can bind to them with no code.

// Equivalent to the Inspector import button:
int rows = table.ImportCsv(csvText);              // delimiter auto-detected
List<float> fps = table.NumericColumn("fps");C#

💡 Troubleshooting

The issues that come up most, and how to fix them.

The overlay didn't appear

Confirm Vantix actually initialized: in Tools → Vantix → Control Center, the Initialized row should say Yes in Play mode. If you added the Vantix Bootstrapper, make sure Show Overlay is ticked. Also check the kill switch — VantixSettings.Enabled must be true and VANTIX_DISABLED must not be defined. The console panel is hidden until you press the backquote (`) toggle key.

Logs aren't persisting between sessions

Logs live in memory by default. Enable File Logging — tick it on the Bootstrapper, set it in the settings asset, or set VantixSettings.FileLogging = true. The RollingFileSink then writes a rolling file you can collect after the session.

IL2CPP build: commands / watches / metrics missing

IL2CPP managed stripping can remove types found only by reflection. Run Tools → Vantix → Generate AOT link.xml + Manifest before building — it scans for the Vantix attributes and writes a link.xml + registration manifest so those types survive. Re-run it whenever you add new decorated types.

Nothing happens on mobile

Vantix runs on mobile (Mono and IL2CPP). For IL2CPP targets generate the AOT link.xml first. The overlay's console toggle defaults to the backquote key, which mobile devices don't have — rebind VantixOverlay.ToggleKey or wire your own UI to ToggleConsole() / SubmitCommand(...).

The overlay looks wrong under URP / HDRP

The overlay is a screen-space UI canvas and works on Built-in, URP and HDRP. If it isn't visible, make sure there is an active EventSystem/UI camera setup for your pipeline and that no full-screen post effect is drawing over the canvas.

A console command isn't found

Make sure the declaring type was scanned — CommandRegistry.ScanType(typeof(YourType)) — or registered manually. Check the command's Category/Id spelling with ConsoleService.Complete(prefix), and confirm it isn't Privileged while AllowPrivileged is off.

❓ FAQ

Quick answers to the questions that come up most.

Do I have to write code to use Vantix?

No. Add the Vantix Bootstrapper component (or GameObject → Vantix → Add Vantix To Scene) and press Play — you get the overlay, HUD and console with zero scripting. The code API (VantixLog, [VantixCommand], VantixTelemetry.Track, …) is there when you want to extend it.

Does it have external dependencies or native plugins?

No. Vantix has no external package dependencies and ships no native binaries — it is pure C#. It runs on Mono and IL2CPP across Unity's targets.

What does the unified timeline give me?

Because every module publishes to one Diagnostics Bus, the SessionRecorder can fold logs, telemetry, metrics and markers onto a single correlated timeline. You can query by time, kind, severity or correlation id to see exactly what surrounded a spike or error — and export the session for a teammate.

Which render pipelines and Unity versions are supported?

Unity 2021.3 and newer (tested through Unity 6), on Built-in, URP and HDRP. The overlay is a screen-space UI canvas, so it is pipeline-agnostic.

Can I strip Vantix from a shipping build?

Yes. The kill switch (VantixSettings.Enabled = false) and the VANTIX_DISABLED define turn the whole platform into a safe no-op without touching your call sites.

Does it catch crashes?

It captures managed (C#) exceptions automatically, dedupes them by signature, persists pending crashes crash-safely and recovers them on the next boot. Native engine/plugin-level crashes aren't catchable in managed code and are out of scope.

How do I extend it?

Implement the public interfaces in Vantix.SDK / Vantix.Core — custom commands, argument converters, log sinks, transports, stores, data sources, metric collectors and crash exporters. See the Scripting API.

Does it run in builds, or only in the editor?

The runtime (bus, console, inspector, logging, performance, telemetry, analytics, crash, session, QA, live-ops and the overlay) runs in builds. The Control Center, Welcome window, Setup Wizard, Dashboard Designer, Project Settings and AOT generator are editor-only tooling.
