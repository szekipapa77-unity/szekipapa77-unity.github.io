CHAPTER 01

Start here: Klondike Daily

Klondike Daily is a standalone editable Unity game template. Play Klondike solitaire by moving eligible cards between tableau columns and foundations, turning the stock and revealing hidden cards. Follow the active claim goal and any move or time limit. The gold-rush trail contains curated claims, a locally generated continuation and a daily deal. Daily content is local, not a remote subscription or cloud service.

Includes 25 curated levels, source-backed generation, a game-specific visual editor and validation, 4 guided helpers, local saving and portrait/landscape scenes. Keep the required private game Kit and publisher-owned Szekipapa77Ads layer. Provider SDK binaries are excluded. There is no bundled HLK, purchases, multiplayer server or remote LiveOps backend. Import only one game Kit into a project because the Kit classes share names.

CHAPTER 02

Requirements, installation and first play

Use Unity 6000.0.62f1, URP 17.0.4 and Unity UI 2.0.0. Install matching Android SDK/NDK/OpenJDK and WebGL modules in Unity Hub. Retain the supplied manifest and ProjectSettings.

  1. Extract the standalone project to a short writable local path, then open it in the matching editor. Wait for package import and compilation.
  2. For native unitypackage import, create a matching URP project and use Assets > Import Package > Custom Package. Import every game, Kit, Szekipapa77Ads and WebGL-template entry.
  3. Run Szekipapa77 > Klondike Daily > Setup. It configures rendering and player settings; review its changes when integrating with existing work.
  4. Active Input Handling must support the classic Input Manager: choose Old or Both. New Input System only is insufficient.
  5. Open Assets/Games/DailyKlondike/Scenes/DailyKlondike_Mobile.unity and press Play. Follow the level card and first-level instructions.
  6. Stop Play mode before editing level assets. Keep all .meta GUIDs. The game uses classic Unity UI Text; do not assume an extra TextMesh Pro import is required.

CHAPTER 04

Gameplay, controls and progression

Play Klondike solitaire by moving eligible cards between tableau columns and foundations, turning the stock and revealing hidden cards. Follow the active claim goal and any move or time limit. The gold-rush trail contains curated claims, a locally generated continuation and a daily deal. Daily content is local, not a remote subscription or cloud service.

The initial bank has 25 curated levels. Read the supplied loader/generator before changing continuation rules. Play the guided opening, ordinary progress, completion and retry paths; preserve saved indexes during a visual reskin. The Mobile scene is portrait and the WebGL-named scene is landscape, but the supplied Build menu selects portrait for both build targets. Select landscape explicitly in your Build Profile if desired. Test a near-startup scene replacement as well as a normal restart.

Visual level editor: worked editing session

Open Szekipapa77 > Klondike Daily > Level Editor. Exact implementation: Editor/DailyKlondikeLevelEditor.cs.

Open the Klondike Daily editor and select an early level. Use Dup or Duplicate before editing. Change its visible name and one rule or board element with the exact controls below. Save explicitly and run the current entry through the editor validation and play controls. The per-game source-control table includes the current brush, geometry, target, rule and AI fields; do not treat hierarchy or resource IDs as display text.

  1. Back up Resources/dailyklondike/Levels/levels.json.
  2. Duplicate a simple early level and edit one small element.
  3. Use the game-specific validation controls and resolve every reported issue.
  4. Save explicitly; stop and restart Play mode, then use Play this level or navigate to the edited index.
  5. Check portrait and landscape and rebuild demo outputs after accepting data changes.

CHAPTER 12

Local saves, reset and migration

HzSave wraps PlayerPrefs and flushes local state on focus loss/quit. WebGL persistence uses browser storage tied to the hosting origin. Clearing site data or changing origin starts a new local save; this is not cloud synchronization. Inspect HzSave/PlayerPrefs calls in the actual game source before altering progression, stars, helper charges or tutorial flags.

Verify fresh launch, a completed arena, helper use, sound options, focus loss and restart. Use a dedicated test profile for resets. Keep technical save keys stable during colour/text reskins. If changing schema or keys, implement and test a migration rather than silently discarding existing users’ progress.

CHAPTER 13

Asset: Assets/Szekipapa77Ads/Resources/AdsSettings.asset. Inspect backend, useGoogleTestIds and missingSdkFallback in the publisher-owned Ads configuration. Buyer projects include adapter/integration code and exclude external provider SDK binaries. WebGL and a missing-provider fallback simulate ads; these are not live commercial impressions.

For real Android ads install the supported provider SDK from its official source into your working project, enter your own app/placement IDs and use test ads first. Verify banner/interstitial/rewarded callbacks on supported hardware. For production use your own IDs and disable simulated missing-SDK fallback. Build tooling rejects unsafe production fallback settings. No IAP, remote backend or HLK is included in this publisher edition.

CHAPTER 16

Troubleshooting

Compile errors: restore matching packages and the full private Kit/Ads layer; only one game Kit belongs in a project. Pink/invisible rendering: run Setup and inspect Graphics and every Quality URP assignment. No input: classic input handling must be enabled; check canvas focus and blocking modals. Missing resources: restore exact paths, .meta GUIDs and importer settings.

Edits do not appear: stop Play, Save in the level editor, reload the canonical bank and check current saved level. Text reverts: update construction and refresh assignments from the exact table. No live ads: provider binaries are deliberately excluded; inspect your installed provider and fallback mode. Scene reload exception: retain owner-lifetime and generation guards on delayed callbacks. WebGL fails: inspect browser Console, compression headers and missing payloads.
