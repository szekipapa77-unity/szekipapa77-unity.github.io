Lumina Layout Unity 6000.0.62f1+

Notch-safe panels and one responsive scale factor that drives every font, padding and border in your UI.

Overview

Lumina Layout solves the two layout problems every shipped mobile UI runs into: the screen is not a rectangle you control, and the screen is not the size you designed for. It ships two drop-in components and four pure static solvers, with no render-pipeline dependency and no setup step.

  • Safe Area — LcSafeArea insets a panel away from notches, rounded corners and the home indicator, per edge, and re-applies on orientation change.
  • Responsive Scaler — LcResponsiveScaler resolves one scale factor from a reference design and hands you scaled font / padding / border / spacing values.
  • Breakpoints — per-screen-config overrides selected by width, orientation, aspect range and touch capability.
  • Flex solver — LcFlexLayout distributes weighted space with per-item margins and spacing.
  • Auto-size & aspect — LcAutoSize fits a RectTransform to content and applies aspect locks (letterbox / envelope).
  • Anchor snapping — LcSnapAnchor plus a full editor menu for the 15 uGUI anchor presets.

Design notes

The two MonoBehaviours are thin. All the real math lives in static classes — LcLayoutMath, LcFlexLayout, LcAutoSize, LcSnapAnchor — which take plain values and return plain values. That split is deliberate: you can unit-test every layout decision without a scene, a Canvas, or play mode, and you can call the solvers from your own components without adopting ours.

The scaler recomputes only when the resolution actually changes. In the steady state it costs nothing per frame and allocates nothing.

Scope. Lumina Layout is a focused layout pack, not the full Lucent UI suite. It contains no widgets, shapes, effects or charts. It installs under Assets/Lucent and shares the Lucent core, so it sits alongside the other Lumina packs without conflict.

Safe Area

LcSafeArea anchors the RectTransform it sits on to Screen.safeArea, so a full-screen panel is inset away from notches, cutouts, rounded corners and the home indicator.

Add it: Add Component → Lucent UI → Layout → Lc Safe Area, on a RectTransform that stretches to fill its Canvas.

Per-edge opt-out

A panel often wants the top inset (notch) but not the bottom, or vice versa. Each edge is independently switchable, and toggling one re-applies immediately while the component is active:

using Lucent.Layout;

var safe = panel.GetComponent<LcSafeArea>();

safe.ApplyTop    = true;   // avoid the notch
safe.ApplyBottom = false;  // let the panel run under the home indicator
safe.ApplyLeft   = true;   // landscape cutouts
safe.ApplyRight  = true;
MemberMeaning
ApplyLeftInset the left edge to safeArea.xMin.
ApplyRightInset the right edge to safeArea.xMax.
ApplyTopInset the top edge to safeArea.yMax.
ApplyBottomInset the bottom edge to safeArea.yMin.
Apply()Fit to the current safe area now, honoring the opt-outs.

Automatic re-application

The component watches for safe-area and orientation changes and re-fits itself. You do not need to call Apply() from an orientation callback — call it only when you have changed the edge flags from code in a frame where you need the result immediately.

Desktop and headless

On platforms where the safe area is the entire screen — desktop, editor, headless CI — the component resolves to a full-stretch no-op. There is no branch to write in your own code and no visual difference between a device without a notch and a desktop build.

Responsive Scaler

LcResponsiveScaler computes one scale factor for the current screen against a reference design, then exposes your authored base values already multiplied by it.

Add it: Add Component → Lucent → Layout → Lc Responsive Scaler.

using Lucent.Layout;

var scaler = GetComponent<LcResponsiveScaler>();

scaler.ReferenceResolution = new Vector2(1920f, 1080f);
scaler.MatchWidthOrHeight  = 0.5f;   // 0 = match width, 1 = match height
scaler.BaseFontSize        = 16f;
scaler.BasePadding         = 8f;

label.fontSize = Mathf.RoundToInt(scaler.ScaledFontSize);
layout.padding = (int)scaler.ScaledPadding;

// Any authored value, scaled on demand:
float scaledIconSize = scaler.Scale(24f);

void OnDisable() { scaler.ScaleChanged -= OnScaleChanged; }

void OnScaleChanged(float scale)
{
    // Fired only when the resolution actually changed.
    Restyle();
}

Scale clamp and blend mode

MinScale / MaxScale bound the result (defaults 0.5 and 4) so an extreme aspect never produces unreadable or absurd UI. UseLogBlend selects how the width and height ratios are combined:

  • Log blend (default, true) — matches Unity's CanvasScaler behaviour exactly. Use this when the scaler runs alongside a CanvasScaler and the two must agree.
  • Linear blend (false) — a straight linear interpolation between the two ratios via LcLayoutMath.ResolveScaleLinear.

Drive targets

The Scale Targets array holds RectTransforms whose uniform localScale is set to the resolved scale on every change. It is the zero-code path: assign a root and the whole subtree scales.

Breakpoints

A breakpoint is a per-screen-config override. It activates when the current screen satisfies all of its constraints, and while active its reference resolution, match value and multiplier replace the scaler defaults.

FieldConstraint
NameLabel for editor/debug only; not used in the math.
MinWidthActivates when screen width ≥ this value (pixels).
OrientationLcOrientationConstraint — restrict to one orientation, or Any.
MinAspect / MaxAspectAspect (width/height) range. 0 means no bound on that side.
TouchLcTouchConstraint — touch, non-touch, or Any.
ReferenceReference resolution while active. (0,0) keeps the scaler default.
MatchMatch width-or-height while active.
ScaleMultiplierExtra multiplier on the resolved scale. 0 is treated as 1.

Selection rule

Among all qualifying entries, the highest MinWidth wins. When two qualifying entries share the same MinWidth, the one listed first wins — so put the most specific entry at the top of the list to break a tie deliberately.

// Phone (default)  -> scaler defaults, no breakpoint needed
// Tablet           -> MinWidth 1024, Touch = Touch
// Desktop          -> MinWidth 1280, Touch = NonTouch

var criteria = new List<LcBreakpointCriteria>();
// ...fill from your breakpoints...
int index = LcLayoutMath.SelectBreakpoint(criteria, metrics);   // -1 = none qualified

The same selection logic is available in a simpler width-only form, LcLayoutMath.SelectBreakpoint(IReadOnlyList<float> minWidths, float currentWidth), when width is the only axis you care about.

Flexible Layout Solver

LcFlexLayout distributes a length among weighted items, reserving fixed margins and inter-item spacing first. It is the solver behind proportional rows and columns, and it is pure — no Canvas, no components, no side effects.

using Lucent.Layout;
using System.Collections.Generic;

var items = new List<LcFlexItem>
{
    LcFlexItem.Weighted(1f),                 // 1 share
    new LcFlexItem(2f, marginBefore: 8f),    // 2 shares, 8px gap before
    LcFlexItem.Weighted(1f),
};

var segments = new List<LcFlexSegment>();
LcFlexLayout.Resolve(available: 600f, items: items, spacing: 12f, output: segments);

// segments[i].Position and segments[i].Size are the resolved placements.

An item with a non-positive weight contributes no size but still reserves its margins — useful for a collapsed pane that must keep its gutter.

Writing the result onto RectTransforms

Apply takes the same inputs plus an axis, container padding and the targets, and writes the resolved segments straight onto the RectTransforms:

LcFlexLayout.Apply(
    LcFlexAxis.Horizontal,
    containerLength: rect.rect.width,
    padding: LcEdges.All(16f),
    spacing: 12f,
    /* items and target RectTransforms */ );

LcFlexAxis.Horizontal flows children left-to-right and Size means width; LcFlexAxis.Vertical flows top-to-bottom and Size means height.

Why a solver and not a LayoutGroup. Resolve is deterministic and allocation-free into a caller-owned list, so you can run it in a test, in a job-prep step, or many times per frame while dragging a splitter — none of which is comfortable with uGUI's layout rebuild cycle.

Auto-Size & Aspect

LcAutoSize is a set of static helpers for sizing a RectTransform. Every entry point runs through Resolve, so you may pass a RectTransform, any Component, or a uGUI Graphic interchangeably — there is no overload hunting.

using Lucent.Layout;

LcAutoSize.SetSize(panel, new Vector2(320f, 180f));
LcAutoSize.SetWidth(panel, 320f);
LcAutoSize.SetHeight(panel, 180f);

// Fit to measured content plus padding
LcAutoSize.FitContent(panel, contentSize, padding: 12f);
LcAutoSize.FitContent(panel, contentSize, new LcEdges(16f, 16f, 8f, 8f));

LcEdges

Float-precision edge insets. Unity's RectOffset is integer-only, which quietly loses sub-pixel padding once a responsive scale is applied — LcEdges exists to avoid that.

var uniform = LcEdges.All(12f);
var custom  = new LcEdges(left: 16f, right: 16f, top: 8f, bottom: 8f);
float h = custom.Horizontal;   // Left + Right
float v = custom.Vertical;     // Top + Bottom

Aspect locking

LcAspectModeBehaviour
WidthControlsHeightKeep width, derive height = width / aspect.
HeightControlsWidthKeep height, derive width = height * aspect.

EnvelopeGrow to cover the current box at the target aspect (crop).
 
// 16:9 video frame, letterboxed inside whatever box it is given
LcAutoSize.ApplyAspect(videoFrame, 16f / 9f, LcAspectMode.FitInside);

// Or compute without writing:
Vector2 size = LcAutoSize.AspectLockSize(current, 16f / 9f, LcAspectMode.FitInside);

Anchor Snapping

LcSnapAnchor resolves and applies the 15 uGUI anchor presets by name, at runtime or from the editor menu. Preset names follow the uGUI inspector layout, so what you read in code matches what you clicked in the anchor popup.

GroupPresets
Point (9)TopLeft TopCenter TopRight MiddleLeft MiddleCenter MiddleRight BottomLeft BottomCenter BottomRight
Vertical stretch (3)StretchLeft StretchCenter StretchRight
Horizontal stretch (3)StretchTop StretchMiddle StretchBottom
 
using Lucent.Layout;

// Snap, adjusting the pivot to match the preset (default)
LcSnapAnchor.Snap(badge, LcAnchorPreset.TopRight);

// Snap but keep the element where it is on screen
LcSnapAnchor.Snap(badge, LcAnchorPreset.TopRight, setPivot: true, keepWorldPosition: true);

// Just read the numbers
LcSnapAnchor.GetAnchors(LcAnchorPreset.BottomCenter, out var min, out var max, out var pivot);
keepWorldPosition. Re-anchoring normally moves an element, because the same offsets mean something different against a new anchor. Pass keepWorldPosition: true to re-anchor without the element appearing to jump — the offsets are recomputed to preserve its current position.

Testing & Determinism

Both components accept injected providers, so you can simulate any device without owning one. This is the difference between a safe-area implementation you can test in CI and one you can only test by borrowing a phone.

// Simulate a notched 1170x2532 portrait screen in an edit-mode test.
safe.ScreenSizeProvider = () => new Vector2(1170f, 2532f);
safe.SafeAreaProvider   = () => new Rect(0f, 102f, 1170f, 2298f);
safe.Apply();

Assert.AreEqual(expectedTopInset, panel.offsetMax.y * -1f, 0.01f);
ProviderOnDefault
SafeAreaProviderLcSafeAreaLive Screen.safeArea
ScreenSizeProviderLcSafeAreaLive Screen size
ResolutionProviderLcResponsiveScalerLive screen resolution
TouchProviderLcResponsiveScalerLive touch capability

The static solvers need no injection at all — they are pure functions over values, so a test is just a call and an assert.

LcResponsiveScaler composes with Unity's CanvasScaler rather than replacing it. Leave the CanvasScaler doing pixel/reference scaling and use Lumina Layout for the authored values — font sizes, padding, borders, spacing — that a CanvasScaler cannot touch. With UseLogBlend left on, both agree on the same scale curve.

FAQ & Troubleshooting

My safe-area panel fills the whole screen in the editor.

Expected. The editor Game view usually reports the full screen as safe. Pick a device profile with a cutout in the Game view aspect dropdown, or inject a SafeAreaProvider to simulate one.

The panel is inset, but it jumps on rotation.

Make sure the RectTransform is a direct full-stretch child of the Canvas and that no parent LayoutGroup is also driving it. Two things writing the same rect will fight; LcSafeArea should own the rect it is on.

Nothing scales when I change the resolution.

The scaler recomputes only when the resolution genuinely changes. If you changed ReferenceResolution or a breakpoint from code, call Refresh() to force a recompute.

Two breakpoints both qualify. Which wins?

Highest MinWidth. On a tie, the entry listed first. Order the list most-specific-first.

Why is my ScaleMultiplier of 0 being ignored?

A multiplier of 0 is treated as 1, so an unset field in a freshly added breakpoint does not collapse your UI to nothing. Use a small value like 0.01f if you genuinely want near-zero.

Can I use the solvers without the components?

Yes. LcFlexLayout, LcAutoSize, LcSnapAnchor and LcLayoutMath are static and depend on nothing in this package beyond Lucent.Core. Call them from your own MonoBehaviours.

Does this conflict with the other Lumina packs or with Lucent UI?

No. All packs install to Assets/Lucent with shared GUIDs on the shared core, so importing several produces an idempotent overwrite rather than duplicate assemblies.

Elements move when I snap their anchors.

That is the default: offsets mean something different against a new anchor. Pass keepWorldPosition: true to Snap.
